# PR-05 — Does the video branch imagine motion?

Pre-registered 2026-08-05, **before any Wan sampling run through `wam.evaluation.dream`**. The
reference arm in §2 was measured first, on CPU, and is reported here rather than in a result
document because it is an input to the thresholds, not an outcome.

Task: T-35. Code: `src/wam/evaluation/dream.py`, `scripts/dream.py`, `tests/test_dream.py`
(40 tests). Venue: the ZeroGPU Space's **dream** tab (`deploy/wan-smoke-space/app.py`).

## 1. The question, and why the existing answer does not settle it

`docs/hf_jobs.md` records a measurement from 2026-07-30 — "the fine-tune is geometry-bound, and
it learned to stand still" — whose third finding is the one that matters:

> **It learned to predict almost no change.** In-distribution motion is **0.73** where the base
> manages 29.5 and a real 0.3 s of demonstration moves considerably more.

Three problems with reading that as settled.

1. **The reference was never measured.** "a real 0.3 s of demonstration moves considerably more"
   is the load-bearing clause and there is no number behind it. 0.73 was compared against the
   *base prior* (29.48), which at that geometry produces, in the same table's words, "psychedelic
   colour noise" — an upper bound on noise, not on plausible motion.
2. **Those clips had no proprioception.** They were generated by `generate_future` inside a stock
   `WanImageToVideoPipeline`. The DiT was trained with the state token concatenated onto the text
   context (`wan_i2v.py:605`); a diffusers pipeline has no state port, so **the input the model
   was trained with was absent**. That is the same *class* of train/inference mismatch T-29 found
   in the frame context, where closing it moved `skill_vs_repeat_pct` by 10.65 pp.
3. **No committed code produced the number.** It was scratch output from the Space, exactly the
   gap PR-04 closed for the corpus screen.

## 2. The reference, measured (2026-08-05, CPU, no Wan weights)

`scripts/dream.py --gt-only`, 40 episodes × 6 evenly-spaced windows of 9 frames from
`datasets/gr00t-apple-grip`, 200 clips after dropping clamped start-of-episode windows. Motion is
mean |frame[t+1] − frame[t]| in 0–255 — the archived definition, now in
`wam.evaluation.dream.motion_energy`.

| quantity | value |
|---|---|
| **gt motion, 120×160 (as recorded)** | **0.958** |
| gt motion, bilinear-resized to 128×160 (the decoded arms' grid) | 0.922 |
| pixel std | 52.4 |
| static fraction (pairs moving < 1/255) | 0.689 |
| per-clip quantiles (0/25/50/75/100) | 0.043 / 0.335 / 0.606 / 1.268 / 5.216 |

Cross-checked against a raw episode with no windowing at all (`gr00t-apple-000000`, 590 frames,
30.05 fps, 19.6 s): consecutive-frame motion mean **0.86**, median 0.425, max 4.94, and 436 of 589
pairs below 1/255. One exact duplicate frame in the whole episode, so the stillness is the task
and the camera, not a codec artifact.

**This corpus barely moves.** 0.27 s of a slow tabletop pick-and-place at 30 Hz through a fixed
camera changes ~1 grey level per frame. Against that, "0.73" is **not** obviously standing still —
it is ~0.8× the recorded motion, where the archived text reads it as ~0. The comparison was
never available before because the denominator had not been computed.

**What this does not do:** it does not overturn the archived finding, because the archived clips
came from a different route (diffusers pipeline, no state token, its own scheduler and CFG) than
`sample_video`. Two numbers from two routes are not a comparison — that is the whole reason for §3.

## 3. Arms, fixed before the run

One GPU call, same clips, same seed throughout.

| arm | what it is |
|---|---|
| `gt` | recorded frames, 120×160 — context only, a different pixel grid |
| **`recon`** | `decode(encode(gt))` — **the reference every ratio divides by** |
| `lora` | WAM's flow, adapter on, text **+ state** conditioning |
| `base` | identical, adapter disabled in place (`set_lora_enabled`) — same weights, same process |
| `base_seed1` | `base` at seed+1 — the null |

`recon` and not `gt` is the denominator because a sampled clip is decoded from latents and
inherits the resize, the temporal stride and the codec. Scoring against raw frames would charge
the flow for all of it.

Free sampling (`anchor_latent_frames=0`) is the **faithful** arm: training noised the whole
9-frame window and denoised the whole window. Anchoring is an intervention, is labelled as one,
and its copied pixel frames are excluded from every motion number (`strip_anchor`).

## 4. Gates and verdicts

Both thresholds are constants in `src/wam/evaluation/dream.py`, in git before the first GPU call.

- **G1 — does it move?** `motion_ratio(lora) = motion(lora) / motion(recon) >= 0.5`
  (`MOTION_FLOOR_RATIO`). Verdict `MOVES` / `STATIC`.
- **G2 — did the fine-tune change the prior?** `d(lora, base) > d(base, base_seed1)`, mean
  absolute pixel difference at matched seed. Verdict `CHANGED` / `INDISTINGUISHABLE`. A fine-tune
  whose dreams differ from the base by less than the base differs from *itself* across sampling
  noise has not been shown to change anything.

| G1 | G2 | verdict |
|---|---|---|
| MOVES | CHANGED | **A** — the branch imagines motion at the trained geometry and training put it there. The archived "learned to stand still" was an artifact of the missing reference and the missing state token; `docs/hf_jobs.md` gets corrected, and the video branch is worth one more question, not a rewrite. |
| STATIC | CHANGED | **B** — training changed the prior and what it changed it towards is stillness. Confirms the archived finding, now with a denominator, and pairs it with the action side's `smoothness_ratio` 0.293: both branches converged on "nothing much happens next". |
| MOVES | INDISTINGUISHABLE | **C** — the clips move because the *base* prior moves. The fine-tune is not visible above sampling noise, which makes the video branch's contribution the base model's, not ours. |
| STATIC | INDISTINGUISHABLE | **D** — nothing to read. Check the sampler against a larger step count and a second seed before recording anything; `tests/test_dream.py` pins the integration against the true field, so a D that survives that is about the checkpoint, not the loop. |

Ties do not arise (both gates are strict inequalities on continuous quantities). A verdict that
flips between seed 0 and seed 1 is no verdict.

## 5. What this cannot answer, stated before the numbers exist

- **Not whether the policy works.** A plausible clip is not a competent policy; the full
  checkpoint reaches L0 and loses to repeat-last-action (−21.80 % windowed).
- **Not whether dreams are VLA training data.** They are not, and no outcome here changes that:
  a generator fitted to 402 success-only episodes cannot produce the **0 failure episodes**, the
  randomized placement or the unfrozen right hand that `PR-04-collection-spec.md` measures as
  what the next corpus needs. Synthesis amplifies diversity; it does not create it. The honest
  version of that question is a screen — `scripts/screen_corpus.py` on a generated corpus,
  against the real corpus's M1 0.6557 / M2 0.3284 / M3 2.0149 — and it is not this document.
- **Not a geometry claim.** Everything is scored at the trained 9 × 128×160. The archived table
  already shows both models fall apart away from where they trained, in opposite directions.
- **Not a competence claim about the video loss.** It was deliberately downweighted to 0.5 so the
  latent flow residual would not dominate the action branch (R-07). Fidelity was never the
  objective, so a low ratio is a finding about the objective as much as about the model.
